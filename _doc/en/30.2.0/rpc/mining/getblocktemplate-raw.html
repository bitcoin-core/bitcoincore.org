--- name: getblocktemplate btcversion: 30.2.0 btcgroup: mining permalink: en/doc/30.2.0/rpc/mining/getblocktemplate/raw/ rawpage: true --- getblocktemplate template_request If the request parameters include a 'mode' key, that is used to explicitly select between the default 'template' request or a 'proposal'. It returns data needed to construct a block to work on. For full specification, see BIPs 22, 23, 9, and 145: https://github.com/bitcoin/bips/blob/master/bip-0022.mediawiki https://github.com/bitcoin/bips/blob/master/bip-0023.mediawiki https://github.com/bitcoin/bips/blob/master/bip-0009.mediawiki#getblocktemplate_changes https://github.com/bitcoin/bips/blob/master/bip-0145.mediawiki Arguments: 1. template_request (object) Format of the template mode (string, optional) This must be set to "template", "proposal" (see BIP 23), or omitted capabilities (array, optional) A list of strings each item (string) rules (array) A list of strings each item (string) longpollid (string, optional) delay processing request until the result would vary significantly from the "longpollid" of a prior template data (string, optional) proposed block data to check, encoded in hexadecimal; valid only for mode="proposal" Result: (one of) option 1: (null) If the proposal was accepted with mode=='proposal' option 2: (string) If the proposal was not accepted with mode=='proposal' option 3: (object) Otherwise version (number) The preferred block version rules (array) specific block rules that are to be enforced each item (string) vbavailable (object) set of pending, supported versionbit (BIP 9) softfork deployments ...
